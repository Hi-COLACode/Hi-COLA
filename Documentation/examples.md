# Small example simulations

[Documentation home](index.md) · [Backend](backend.md) · [Plotting](plotting.md)

`examples/small_simulations` contains complete, small runs for four cases:

| Case | Model | Frontend tables |
| --- | --- | --- |
| `gr` | GR | None |
| `cubic_galileon` | Cubic Galileon (Horndeski) | Generated by the Horndeski frontend from `cubic_galileon.ini` and `numerical.ini` |
| `kmouflage` | K-mouflage | Analytic ΛCDM expansion with manufactured coupling and screening tables |
| `lightcone` | GR lightcone from redshift 0.25 | None |

Each simulation uses 16³ particles in an 80 Mpc/h box, a 32³ force mesh, and five timesteps from redshift 49 to zero. Outputs include power spectra and particle snapshots; the lightcone case also writes ASCII particle crossings and replicates the box to cover its radial extent, which makes it the most expensive case. These runs demonstrate execution, not convergence. The K-mouflage case demonstrates the backend rather than a calibrated physical K-mouflage model.

## Run all examples in Docker

From the repository root:

```sh
docker build -t hicola-runtime .
docker run --rm -it --user "$(id -u):$(id -g)" -v "$PWD:/workspace" hicola-runtime
```

Inside the container:

```sh
python examples/small_simulations/run_simulations.py \
  --work /workspace/example-output --prefix /usr \
  --make-arg LUA_INCLUDE=/usr/include/lua5.4 \
  --make-arg 'LUA_LINK=-llua5.4 -ldl'
```

The runner builds COLASolver, generates the frontend tables, runs each simulation, and draws its figures into `<case>/plots/` with the [plotting commands](plotting.md). Modified-gravity cases are plotted against the GR run. `--work` must be a new directory; it receives build commands, process IDs, logs, and outputs. Compilation writes build products into the source checkout. Use `--cases gr` to run selected cases and `--ranks 2` for two MPI processes.

Outside Docker, the same command works with a C++ compiler, make, MPI, MPI-enabled FFTW, GSL, Lua, and the Python package installed from the checkout (`python -m pip install -e .`). Pass the dependency prefix with `--prefix` and Lua flags with `--make-arg`.

## Input files

`backend_minimal.lua` holds the shared simulation settings: box size, particle count, meshes, and timesteps. `gr.lua`, `cubic_galileon.lua`, `kmouflage.lua`, and `lightcone.lua` load it with `dofile` and select their model and output settings. The runner's generated Lua wrapper supplies only file paths.

A built backend can run an example directly from the repository root:

```sh
mkdir -p Hi-COLA_Output/gr/output
mpiexec -n 1 HiCOLA/FML/COLASolver/nbody examples/small_simulations/gr.lua
```

Create the directory named by `output_folder` first. Direct modified-gravity runs read their tables from `Hi-COLA_Output/frontend/`. Generate the cubic Galileon tables with:

```sh
python -m HiCOLA.Frontend.generate_simulation_input \
  examples/small_simulations/cubic_galileon.ini \
  examples/small_simulations/numerical.ini
```

The K-mouflage tables come from the runner's manufactured-table generator, not the Horndeski frontend.
