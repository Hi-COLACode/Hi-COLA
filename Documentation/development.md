# Development

## Tests

```sh
python -m pip install -e '.[tests]'
python -m unittest discover -s tests -v
python -m coverage run -m unittest discover -s tests && python -m coverage html
```

The unit tests cover the Python frontend, plotting tools, and backend launcher, not the C++ code; CI runs them on Python 3.11. [tests/README.md](repo:tests/README.md) explains the references, tolerances, and expected failures.

The **Regression tests** workflow runs the GR, cubic Galileon, and K-mouflage [examples](quickstart.md#run-the-example-simulations) on a pinned baseline and on the candidate revision. **Regression summary statistics** compares power spectra, expansion and growth tables, particle counts, and velocities within explicit tolerances and should be a required check; **Regression particle reproducibility** compares particles and force grids and is advisory.

The **Build** workflow builds and checks the pip and conda packages on Linux, macOS, and Windows; [RELEASING.md](repo:RELEASING.md) covers publishing them.

## Documentation

```sh
python -m pip install -r requirements-docs.lock
python -m sphinx -W --keep-going -b html Documentation Documentation/_build/html
```

The site uses Sphinx with MyST Markdown; API pages come from NumPy-style docstrings. `requirements-docs.lock` pins Python 3.12 dependencies, compiled from `requirements-docs.txt` and `pyproject.toml`.

**Figures** are generated by `Documentation/figures.py` on every build. The frontend figure needs only Python. The simulation figures need a completed example run passed as `DOCS_SIMULATION_WORK`; otherwise a note replaces them:

```sh
python examples/small_simulations/run_simulations.py --work /tmp/hicola-examples --cases gr cubic_galileon
DOCS_SIMULATION_WORK=/tmp/hicola-examples python -m sphinx -W --keep-going -b html Documentation Documentation/_build/html
```

**Publishing.** The **Documentation** workflow builds pull requests without publishing. Relevant pushes to the default branch run the example simulations, build, replace `current/` on the `gh_pages` branch, commit it, and deploy that tree with GitHub Pages Actions. Set **Settings → Pages → Source** to *GitHub Actions* and allow the default branch and release tags in the `github-pages` environment. A published GitHub release is archived once under its tag name, reusing matching current HTML or building the tag with its own lock file; existing archives are never rebuilt or overwritten. The site root opens the newest release (marked `latest` in `versions.json`), or `current/` before the first release. `versions.json` drives the version selector in the sidebar footer and the banner shown on the development version and on releases other than the newest (marked `latest`), and each version directory records its `source-commit.txt`.

**Links.** The **Links** workflow checks the built pages with Lychee. Broken local links and anchors fail it; make **Links / local-links** a required check. External links in the pages and source files are checked too, but failures only produce the `documentation-link-report`.
